## Workflow

`beethoven` develops an ensemble air quality modeling workflow: download source data, calculate covariates at monitoring sites and prediction locations, fit base and meta learners, and generate predictions.

The Snakemake implementation now resides in this project. The root `Snakefile` loads `config/config.yaml` and the rules in `inst/rules/`; those rules dispatch R scripts from `inst/scripts/` through Apptainer containers. The default output is `output/dt_pred_base_sptmpl.qs`, which requires both fitted base learners and prediction-grid covariates.

The current workflow downloads AQS observations and NARR/HMS covariates, prepares monitoring-site features, fits elastic-net base learners, and prepares H3 grid predictions. Grid preparation now uses the `e` tier (previously `f`), and model prediction uses the `f` tier (previously `g`). Meta-learner fitting remains a placeholder in `d04_meta.R`.

## Directory structure

The project combines R package functions with Snakemake rules and stage-specific scripts. The outline shows the active workflow files and main package directories; archived material is collapsed under `inst/archive/`. Each rule file and R workflow script has a short description.

├── run.sh                           # SLURM and Apptainer launcher
├── .github/
│   └── workflows/

├── config/
│   └── config.yaml                  # Dates, paths, grid resolution
├── inst/
│   ├── rules/
│   │   ├── a01_initiate.smk         # Initialize dates and years
│   │   ├── b01_download.smk         # Download AQS, NARR, HMS

│   │   ├── d01_model.smk            # Resample and fit models
│   │   ├── e01_grid.smk             # Prepare grid and covariates
│   │   └── f01_predict.smk          # Predict with base learners
│   └── scripts/
│       ├── a01_initiate.R           # Generate dates and chunks
│       ├── b01_aqs.R                # Download AQS observations

## Pipeline

| Tier | Script Prefix | Rules | Behavior and principal outputs |
| --- | --- | --- | --- |
| initiate | `a` | `initiate` | Generates the configured date sequence, included years, and date chunks in `chr_init_dates.qs`, `int_init_years.qs`, `list_init_dates.qs`, and `list_init_datesj.qs`. |
| download | `b` | `download_aqs`, `download_narr`, `download_hms` | Downloads source files and saves `list_dl_aqs.qs`, `list_dl_narr.qs`, and `list_dl_hms.qs`; also saves the 24 selected NARR variables in `chr_iter_narr.qs`. |
| calculate | `c` | `calculate_aqs`, `calculate_narr`, `calculate_hms`, `calculate_merge` | Prepares AQS monitoring locations and PM2.5 observations, calculates NARR/HMS covariates, and merges the feature tables by `site_id` and `time` into `dt_feat_merge_sptmpl.qs`. |
| model | `d` | `model_cvrset`, `model_base` | Creates CV resamples and common settings in `list_base_cv_rset.qs` and `list_base_params_static.qs`. Fits elastic-net models in `list_base_fit_elnet.qs` and joins their out-of-sample predictions to the training data in `dt_base_aqs_sptmpl.qs`. |
| grid | `e` | `prediction_grid`, `prediction_narr`, `prediction_hms`, `prediction_merge` | Builds `sf_pred_grid_sp.qs`, calculates NARR/HMS grid covariates, and merges them into `dt_pred_merge_sptmpl.qs`. |
| predict | `f` | `predict_base` | Applies the fitted base learners to grid covariates and declares `dt_pred_base_sptmpl.qs` as its output, with location/time fields and one `pred_###` column per model. |

All serialized outputs are written under `output/` relative to the project root. The `all` rule requests `dt_pred_base_sptmpl.qs` and has no processing tier. After monitoring-site features are merged, the modelling and grid branches can proceed independently; `predict_base` depends on both the fitted models and the merged grid covariates. There is no active meta-learner rule.

`model_cvrset` currently omits incomplete rows, removes `Event.Type`, and uses `Arithmetic.Mean` as the outcome. Its development settings request 20 distinct spatiotemporal CV partitions, five folds, CRS 5070, and 250,000-meter spatial cells. `model_base` tunes the CPU `glmnet` engine's mixture and penalty with a grid size of three, normalization enabled, and the `mae` metric. Out-of-sample predictions are joined back to the training data using `.row` identifiers.

Grid generation uses the North Carolina county example bundled with `sf`, unions its geometry, and generates H3 cell polygons at the configured resolution. The cell IDs are stored as `site_id` in `sf_pred_grid_sp`. The grid merge joins NARR and HMS tables by `site_id` and character-valued `time`.

The grid identifier update is still incomplete: `e02_narr.R` references `chr_pred_h3r8` in its variable merge, although that object is no longer supplied, and `f01_base.R` still reads `h3r8_id` when deriving cell coordinates. These references need alignment with `site_id` before the full prediction path is ready.

## Configuration and execution

| Setting | Current value | Use |
| --- | --- | --- |
| `chr_config_daterange` | `2021-01-01` through `2022-12-31` | Inclusive dates for downloading and processing data. |
| `chr_config_dir` | `beethoven/beethoven/input/` | Download directory, resolved relative to `$HOME` by the rules. |
| `int_config_radii` | `1000`, `5000`, `10000` | Configured buffer radii in meters; current NARR/HMS scripts explicitly use `radius = 0`. |
| `int_grid_res` | `5` | H3 resolution for the development grid. |

Snakemake dispatches each script through the image declared in its rule when `--use-apptainer` is enabled:

| Container | Tiers |
| --- | --- |
| `inst/container/sif/container_covariates.sif` | `a` initiate, `b` download, `c` calculate, and `e` grid. |
| `inst/container/sif/container_models.sif` | `d` model and `f` predict. |

The container definitions and build scripts reside under `inst/container/def/` and `inst/container/sh/`. Both image definitions install the `beethoven` package from `NIEHS/beethoven@mm-1013`. NARR/HMS scripts also source the local mirai-enabled helpers in `R/amadeus.R`. The models image includes CUDA support, while the current elastic-net specification runs on the CPU.

`run.sh` launches Snakemake within one SLURM allocation on the `geo` partition, requesting 20 CPUs and 10 GB of memory. It enables Apptainer and writes logs under `slurm/`. Its core limit comes from the first script argument, then `SLURM_CPUS_PER_TASK`, then a fallback of `1`; it does not request GPUs or pass `--nv`.

NARR downloads start 50 local mirai workers; HMS downloads and NARR/HMS calculations start 100. CV preparation and base-model fitting currently start 20 workers, one per model run. Grid prediction applies the fitted workflows sequentially. These worker counts are set in the scripts independently of Snakemake's core limit, and the rules declare no corresponding thread resources. The worker pools therefore need to be accounted for when sizing the SLURM allocation. Downloads, serialized outputs, runtime state, logs, and container images are local artifacts ignored by Git.
